# 목회AI연구소 홈페이지

목회데이터연구소의 정보 구조, Stanford HAI의 기관 구성, FaithTech의 신앙·기술 콘텐츠 방식, FAR.AI의 교육·행사 경험을 참고해 재구성한 Next.js 운영형 홈페이지입니다. 공개 홈페이지와 관리자 운영실이 같은 데이터 구조를 사용합니다.

## 구현 기능

- 문의, 강의 요청, 공개 일정 신청 통합 접수
- 신청 데이터 상태 관리: 새 접수, 연락 완료, 확정, 종료
- 빈 게시판에서 칼럼과 공지를 하나씩 등록·수정하고 공개/초안 전환, 메인 노출 관리
- 강의·세미나 일정 등록, 신청 마감 및 재개
- Firebase Firestore/Auth 연결 및 로컬 개발용 데모 저장소
- 연구·콘텐츠, 교육, 사역·프로젝트, 소식을 분리한 기관형 다중 페이지 구조
- 관리자에서 수정한 최신 공지와 일정의 홈페이지·상단 배너 자동 반영
- 데스크톱·태블릿·모바일 반응형 레이아웃

## 주요 경로

- `/` 홈페이지
- `/apply` 문의 및 강의 신청
- `/schedule` 공개 일정
- `/columns` 칼럼
- `/insights` 목회 인사이트와 연구 가이드
- `/prompts` 목회 프롬프트 자료실
- `/projects` 사역과 프로젝트
- `/notices` 공지
- `/archive` 8월·9월 이미지 자료실
- `/login` 관리자 로그인
- `/admin` 운영 현황
- `/admin/applications` 신청 관리
- `/admin/content` 칼럼·공지 관리
- `/admin/schedules` 일정 관리

## 로컬 실행

```bash
npm install
npm run dev
```

개발 모드에서 Firebase 환경값이 없으면 로그인 페이지의 `로컬 관리자 화면 열기` 버튼이 나타납니다. 이때 데이터는 현재 브라우저의 localStorage에만 저장됩니다. 예시 칼럼·공지·일정은 제공하지 않으며 빈 상태에서 시작합니다.

## 운영 저장소 권장안

실제 운영 데이터는 Supabase(Postgres, Auth, Storage)를 원본으로 사용하고 NAS는 이미지 원본과 정기 백업 보관용으로 병행하는 구성을 권장합니다. 현재 코드는 Firebase와 로컬 저장소를 사용하므로 Supabase 전환은 프로젝트와 관리자 계정을 만든 뒤 별도로 연결해야 합니다.

## Firebase 운영 연결

1. `.env.example`을 복사해 `.env.local`을 만듭니다.
2. Firebase 프로젝트의 웹 앱 환경값을 입력합니다.
3. Firebase Authentication에서 이메일/비밀번호 로그인을 활성화하고 관리자 계정을 만듭니다.
4. 관리자 계정 토큰에 `admin: true` custom claim을 부여합니다.
5. `firestore.rules`를 Firebase 프로젝트에 배포합니다.

관리자 custom claim이 없는 계정은 로그인하더라도 Firestore의 신청 데이터와 관리 기능에 접근할 수 없습니다.

## 이미지 준비

필요한 사진, 썸네일 규격, 카테고리별 이미지 방향은 [이미지 가이드](./docs/IMAGE_GUIDE.md)에 정리되어 있습니다.

8월·9월 배포 자료에서 가져온 이미지 목록은 [이미지 라이브러리](./docs/IMAGE_LIBRARY.md)에 정리되어 있습니다.

기존 연구소 자료 615개를 조사한 결과와 홈페이지에 선별 반영한 파일은 [원본 자료 선별 기록](./docs/SOURCE_MATERIALS.md)에서 확인할 수 있습니다.

콘텐츠 등록과 신청 관리 순서는 [운영 가이드](./docs/운영_가이드.md)를 참고하세요.
